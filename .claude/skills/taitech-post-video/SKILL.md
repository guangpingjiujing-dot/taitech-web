# taitech-post-video

サイトの動く教材を、そのまま SNS 投稿用の短尺動画にするスキル。

**手で画面収録しない。** 必ず Playwright で撮る。理由は再現性で、題材・速度・構図・文言を
変えた撮り直しがコマンド 1 発で済む。手収録はマウスの揺れ・撮り漏れ・尺のブレが毎回入る。

**既存の実装例が最良のリファレンス**: `scripts/demo-video/`
(`playground-demo.gen.ts` = 進行 / `overlay.ts` = 注釈 / `playwright.config.ts` = 専用設定)。
新しい動画を作るときはこれを複製して中身を差し替えるのが最短。

```bash
npm run gen:demo-video   # 本番ビルドを立ち上げて録画 → MP4 まで出力
```

## 1. なぜ動画なのか (前提)

`docs/strategy/growth.md` の打ち手 A。要点だけ再掲する。

- X はネイティブ動画を優遇し、**外部リンク付き投稿のリーチは落ちる**。
  だから **投稿本文に URL を貼らない**。URL は動画のエンドカードとリプライ・固定に置く
- 同じ素材が YouTube Shorts / TikTok に流用できる
- サイトの価値が「動くこと」にある教材 (Playground / クイズ / 可視化) は、
  静止画やテキストで説明した瞬間に価値の大半が消える

## 2. 動画の設計原則

### 2.1 見せる中身は 1 つに絞る

1 本で 2 つ以上のことを言おうとしない。デモ動画は「この画面のこれが動く」を
1 つだけ見せて終わる。既存例は「1 行ずつ実行すると変数の値が動く」だけを見せている。

尺は **15〜25 秒**。題材は次の条件で選ぶ。

- 毎ステップ目に見えて変化する (値が動く / 図が変わる)
- 10 ステップ前後で終わる
- サイトの主張が自然に出る (例: 擬似言語の配列は 1 始まり)

### 2.2 注釈は必須。ただし 3 つまで

**X は動画をミュートで自動再生する。** 無音・無テキストだと最初の 1〜2 秒で
何の画面か伝わらずスクロールされる。一方でサイトはモノクロの最小構成なので、
要素を増やすと途端に浮く。入れるのは次の 3 つだけ。

| 要素 | 役割 |
|---|---|
| キャプション | 画面下の 1 行。今どこを見ればいいかを言う |
| リング | 注目させたいパネルを囲む枠。視線誘導 |
| エンドカード | 最後に URL。本文にリンクを貼らない運用なので URL を伝えられるのはここだけ |

### 2.3 用語を省略しない

**「擬似言語」だけでは何の擬似言語か伝わらない。** 冒頭のキャプションとエンドカードでは
必ず試験名まで言う (例: 「基本情報 科目B の擬似言語」)。表記は
1 日 1 問の投稿画像 (`scripts/post-images/`) と揃える。

**絵文字は使わない** (`docs/x-posts/README.md` の方針)。

### 2.4 キャプションはその区間ずっと真であること

「いま更新されている」のような瞬間的な断定は、区間の終わりで必ず嘘になる。
「変数の値を1行ずつ追える」のような**能力の記述**にすると全区間で正しい。

これは実際に事故った箇所。当初「変数の値が毎ステップ更新される」と書いたため、
値が止まった `endfor` の区間で画面と食い違い、それを実行時判定で消そうとして
さらに壊した (§4.4)。**文言で解決できるものを実行時ロジックで解決しない。**

## 3. 実装の型

### 3.1 専用の Playwright config を切る

E2E (`playwright.config.ts`, testDir `./tests`) とは必ず分ける。

```ts
export default defineConfig({
  testDir: ".",
  testMatch: "*.gen.ts",          // テストではないと分かる名前にする
  workers: 1,
  timeout: 180_000,
  outputDir: "../../docs/x-posts/<name>/.raw",  // docs/ は .gitignore 済み
  use: {
    baseURL: "http://localhost:3000",
    viewport: { width: 1280, height: 720 },
    video: { mode: "on", size: { width: 1280, height: 720 } },
  },
  webServer: {
    command: "npm run build && npm run start",  // dev サーバーは不可 (§4.1)
    url: "http://localhost:3000",
    reuseExistingServer: true,
  },
});
```

`package.json` に `"gen:<name>": "playwright test --config scripts/<dir>/playwright.config.ts"`
を足す。`npx playwright test --list` が 169 件のままであること (E2E に混入していないこと) を確認する。

### 3.2 デモ対象の状態はディープリンクで作る

エディタに文字を打ち込む操作を録画するのは遅くて壊れやすい。
`?code=` のような既存のディープリンクがあれば、それで初期状態を作る。

### 3.3 注釈は録画中の DOM に差し込む

ffmpeg の `drawtext` ではなく **DOM オーバーレイ**でやる。日本語フォントの扱いが確実で、
サイトの配色をそのまま使え、位置調整が CSS で効く。
`overlay.ts` の `installOverlay()` を `page.evaluate(installOverlay)` で注入し、
`window.__demo.caption() / ring() / endCard()` で操作する。

`page.evaluate` に渡す関数は**モジュールスコープの変数を参照してはいけない**
(関数のソースだけがブラウザに渡るため)。

## 4. ハマりどころ (すべて実際に踏んだ)

### 4.1 録画は page 生成時点から始まっている

`goto` を待ってから周辺 UI を隠すと、**素のページ (ヘッダー・書籍サイドバー込み) が
冒頭 1 秒ほど録画に入る**。X で最も重要な最初の 1 秒がこれで潰れる。

対策は 2 段構え。

1. `page.addInitScript` で初回描画の**前**から `html { visibility: hidden }` を注入し、
   準備が終わってから解除する
2. 隠していた区間の長さを実測し、MP4 変換時に `-ss` で切り落とす
   (無地で始まるのも損なので)

`display:none` ではなく **`visibility:hidden`**。レイアウト計算を残さないと
リングの位置決めに使う `getBoundingClientRect` が取れない。

### 4.2 隠すと locator が全滅する

`visibility:hidden` の間は、

- 既定の `waitFor()` (可視待ち) は永久に解決しない
- **`getByRole` は非表示要素のロールを解決しない**ので `state: "attached"` でも一致しない

表示を戻す前の待機は locator を使わず、`querySelector` + `textContent`
(visibility を見ない) だけで行う。locator は表示を戻したあとのクリックにだけ使う。

### 4.3 「対象だけ残す」は祖先の兄弟を隠す + 祖先の display も潰す

セレクタで `header` や `aside` を名指しすると、ページ構成を変えるたびに壊れる。
対象要素から `body` まで祖先を辿り、各階層の兄弟をまとめて隠す。

それだけでは足りない。**祖先の `display` / `width` / `maxWidth` / `padding` / `margin` も
潰す**こと。サイドバー用の CSS grid はカラム幅を確保し続けるので、兄弟を消しただけでは
対象が左寄りのまま小さく残る (記事本文の段組み幅 ≒ 672px に閉じ込められる)。

その上で `body` を flex 中央寄せにし、対象に `max-width` を与える
(幅を絞らないとエディタだけ間延びしてスカスカに見える)。

### 4.4 注釈の切り替えはステップ数で決め打ちしない

決め打ちにすると題材を変えた瞬間に画面と注釈がズレる。**実際の DOM の変化**
(パネルのテキスト) を 60ms 間隔で読んで切り替える。

ただし**「値が変わらなかったステップ」を位相の区切りに使ってはいけない**。
値が動かないステップは `endfor` だけではないし、そもそも **最初のクリックは
ハイライトを 1 行目に置くだけで何も実行しない** ので、そこで誤発火する。
実際にこれでリングが 1.5 秒しか出ない状態になった。

安全な設計:

- 起点は「**最初に**値が変化した瞬間」(これは誤検知しない)
- 終点は「出力が出た瞬間」(これも誤検知しない)
- その間はずっと同じ注釈を出しっぱなしにし、**文言で正確さを担保する** (§2.4)

### 4.5 判定はクリック直後から。待機明けにまとめて見ない

ステップの待機 (STEP_MS) が終わってから判定すると、画面はもう変わっているのに
注釈だけ約 0.85 秒遅れて切り替わり、はっきりズレて見える。
クリック直後から短間隔でポーリングする。

### 4.6 リングの位置をアニメーションさせない

`transition` に `top` / `left` を入れると、`width` / `height` は即時反映なので
**移動途中に大きさの合わないコマが写る**。リングは常に「消えている間」に置き直すので、
`opacity` だけ transition すればよい。

### 4.7 X は WebM を受け付けない

Playwright の録画は WebM。X に上げられるのは **MP4 (H.264) か MOV** のみ。

```bash
ffmpeg -y -ss <preroll> -i in.webm \
  -c:v libx264 -pix_fmt yuv420p -movflags +faststart -an out.mp4
```

- `-pix_fmt yuv420p`: 付けないと一部プレイヤーで再生できない
- `-an`: 無音デモなので音声トラックなし
- ffmpeg が無い環境では**落とさず警告して手順を案内する**実装にしておく

### 4.8 ハイライトは「次に実行する行」

少なくとも FE Playground では、ハイライト行は実行済みの行ではなく
**次に実行する行**を指す。`print(...)` がハイライトされている時点ではまだ出力は出ない。
題材とキャプションを設計するときにここを取り違えない。

## 5. 検証は必ず動画から行う

**スクリーンショットだけで確認したことにしない。** スクリーンショットは
「その瞬間に意図した状態」しか写さないので、タイミングのズレは絶対に見つからない。
実際、静止画では問題なく見えたものが動画では 4 箇所ズレていた。

### 5.1 全体を 1 枚で見る (最初にこれをやる)

```bash
ffmpeg -v error -i out.mp4 -vf "fps=1,scale=440:-1,tile=5x4" timeline.png
```

1 秒 1 コマのコンタクトシート。**どの注釈がどの区間出ているかが一目で分かる**ので、
「リングが短すぎる」「キャプションが残り続けている」の類はここで全部見つかる。

### 5.2 気になった箇所をピンポイントで抜く

```bash
for t in 12.8 13.0 13.2 13.4; do
  ffmpeg -v error -ss $t -i out.mp4 -frames:v 1 "f-$t.png"
done
```

切り替わりの前後は 0.2 秒刻みで見る。フェードイン (0.28 秒) のぶんは遅延ではないので
そこと本当のズレを混同しない。

### 5.3 チェックリスト

- [ ] **0.0 秒**の時点で余計な UI (ヘッダー / サイドバー / 記事本文) が写っていない
- [ ] 冒頭 1〜2 秒で「何の画面か」が読める (試験名まで書けているか)
- [ ] リングが「見せたい変化が起きている区間」を通して出ている
- [ ] キャプションがその区間ずっと真になっている
- [ ] 出力・結果が出た瞬間と注釈の切り替えが揃っている
- [ ] エンドカードに URL が出ている
- [ ] 絵文字を使っていない
- [ ] MP4 が生成されている (WebM のまま投稿しようとしていない)
- [ ] `npx tsc --noEmit` が通る / `npx playwright test --list` が E2E 件数のまま

## 7. 縦型 (Shorts / TikTok) について

現状の実装は横長 1280x720 のみ。縦型が要るときは viewport を変えて撮り直すのが正道
(横動画を後からクロップすると、右のパネルか左のエディタのどちらかが必ず切れる)。
`installOverlay` のキャプション位置とエンドカードの文字サイズは縦型で要調整。
