## 1. 用語整理

### 1-1. 各用語の定義

| 用語 | 正式名称 | 焦点 |
|---|---|---|
| **SEO** | Search Engine Optimization | 検索エンジンのランキングアルゴリズムに対する最適化 |
| **AEO** | Answer Engine Optimization | 質問に対する「端的な回答」として選ばれること |
| **LLMO** | Large Language Model Optimization | LLMに引用・推奨されること（技術的側面を強調した呼称） |
| **GEO** | Generative Engine Optimization | 生成AIの回答生成プロセスへの引用全般（海外で定着） |
| **AIO** | AI Optimization | AI検索最適化全般を指す最も広い総称 |

**実務上の結論:** これらは対立概念ではありません。AEO・LLMO・GEO・AIOで行う施策内容はほぼ重なっており、どの立場の読者に説明するかで呼び分けられているだけです。FAQ形式の整備や見出しで質問に直接答える構造は、どの枠組みでも中核施策になります。

### 1-2. Google自身の公式見解

2026年5月15日、Googleは Search Central に「Optimizing your website for generative AI features on Google Search（Google検索の生成AI機能に向けたウェブサイト最適化）」を公開しました。John Mueller氏がSearch Central Blogで告知し、「Generative AI fundamentals」という新しいナビゲーション区分の下に置かれています。

このドキュメントの中核メッセージは明快です。

> Google検索の観点からは、生成AI検索への最適化は検索体験への最適化であり、つまり依然としてSEOである。

AI OverviewsもAI Modeも、従来のGoogle検索と完全に別のシステムで動いているわけではなく、同じランキング・品質システムの上に構築されています。GoogleはRAG（検索拡張生成）や**クエリのファンアウト**（より完全な回答を作るために関連する検索を複数投げて情報を集める処理）といった技術を用いていると説明しています。

Google社員のGary Illyes氏、Cherry Prommawin氏もSearch Central Liveで「GEOやAEOに別個のフレームワークは不要」という立場を示しており、それが公式ドキュメントとして明文化された形です。

### 1-3. したがって取るべき戦略

```
❌ SEOとは別に「LLMO対策」プロジェクトを立ち上げる
✅ SEOの土台を維持したまま、「引用されるための要素」を上に足す
```

実務者からは「SEOに良いことがGEOに良い」ケースが約8割、という体感も語られています。

## 2. 前提となる環境変化

### 2-1. ゼロクリックの本格化

- Ahrefsの2025年12月調査では、AI Overviewsが表示された場合、**検索1位サイトのCTRがグローバルで約58%、日本国内でも約38%低下**したと報告されています。
- 2026年5月時点で、**AI Overviewsの月間アクティブユーザーは25億人超、AI Modeは10億人を突破**（Google発表）。
- AI Modeは長い質問、追跡質問、比較、マルチモーダル検索に対応しており、**ユーザーがサイトを訪問する前に購買判断が形成される**構造になっています。

### 2-2. 「順位」と「引用」は別チャネル

ここは調査によって数字が割れており、断定を避けるべき領域です。

| 調査 | 内容 | 示唆 |
|---|---|---|
| Moz（2026年、4万クエリ） | Google AI Mode引用の**88%**がオーガニック上位10位に登場しない | 別チャネル |
| Zhang et al.（arXiv:2512.09483） | AI引用ドメインの**37%**が従来検索結果に一切現れない | 別チャネル |
| Ahrefs（86.3万キーワード） | AI Overviews引用の**38%**がGoogle上位10位のページ由来 | 地続き |

**解釈:** 「SEOで勝てばAI引用も取れる（ただし追加作業あり）」という側面と、「SEOだけでは届かない領域がある」という側面の両方が事実です。順位トラッキングだけを見ていると判断を誤ります。

## 3. 評価されるコンテンツの条件

### 3-1. 最上位の原則 ― 「検索を終わらせられるか」

従来SEOでもAI検索でも、評価軸は結局ここに収束します。自サイトを訪問したユーザーがそこで検索を終了できる有益なコンテンツが作れていれば、コアアップデートでダメージを受ける可能性は低くなります。

### 3-2. 非コモディティであること（Google公式の第一条件）

Googleのガイダンスが最初に挙げるのが以下です。

> 役に立ち、信頼でき、人間本位（people-first）で、**コモディティでない**コンテンツを作ること。一般常識を超える価値を提供する、独自かつ専門家主導のコンテンツに注力すること。

**なぜAI時代に決定的なのか:** 他所にある情報の焼き直しは、AIがすでに何百ページも学習済みです。引用する必然性がありません。派生的な「me-too」コンテンツには引用価値がなく、ベンチマークレポートや独自データは競合が容易に模倣できない堀（moat）になります。

**具体的な資産の例:**
- 自社サービスから得られる集計データ・業界ベンチマーク
- 独自アンケート調査
- 施工事例・支援事例（数値と条件つき）
- 実測・検証レポート
- 現場担当者しか知らない失敗パターン

### 3-3. E-E-A-T ― とりわけ Experience

Googleの検索品質評価ガイドラインで定義される4要素です。

| 要素 | 内容 | 具体的な打ち手 |
|---|---|---|
| **Experience（経験）** | 実体験に基づいて作られているか | 自社の支援事例、実際に使った/訪れた記録、写真・データ |
| **Expertise（専門性）** | テーマの知識・スキルに基づくか | テーマを絞った継続発信、有資格者の執筆 |
| **Authoritativeness（権威性）** | そのテーマで権威があるか | 業界メディア掲載、講演・寄稿、被リンク |
| **Trustworthiness（信頼性）** | 内容が信頼できるか | 情報源・執筆者・監修者の明記、更新日、運営者情報 |

2026年3月のコアアップデートではE-E-A-Tの評価精度向上が最大の変更点とされ、業界調査では55%以上のサイトで順位変動が観測されました。2022年12月にE-A-Tへ「Experience」が加わって以降、**一次情報（実際に使った・体験した・訪れた）の価値が一貫して上がり続けています**。

### 3-4. 具体性 ― 数値・出典・引用を埋め込む

プリンストン大のGEO研究（1万クエリ、2024年）では、**引用（citations）・統計（statistics）・引用文（quotations）の追加が、それぞれページのAI可視性を約30〜40%押し上げた**と報告されています。

```
❌ 「多くの企業が生成AIの活用を進めています」
✅ 「2026年の調査では消費者の3分の1以上が、従来の検索エンジンではなくAIツールから
    リサーチを開始していると報告されています（出典・調査年つき）」
```

これは従来SEOでも被リンクを自然に集める要因であり、**新旧で完全に利害が一致する数少ない施策**です。

### 3-5. 網羅性より解決性

「キーワードを網羅した長文を書く」という手法だけに頼る時代は終わっています。

- 文字数稼ぎの一般論の前置き → AI検索では要約されて終わる／従来SEOでも評価されない
- 結論を先に出し、根拠を後ろに置く構成が、人間にもAIにも有利
- 長文でも、冒頭に明確な回答があり、構造化された具体的事実を含んでいれば引用されます

### 3-6. 検索意図とページ型のマッチ

同じキーワードでも、必要な答えの形は違います。

| 意図 | 求められるページ型 |
|---|---|
| Know（知りたい） | 解説記事、定義、図解 |
| Do（やりたい） | 手順、ツール、テンプレート |
| Compare（比較したい） | 比較表、レビュー、リスト記事 |
| Buy（買いたい） | 製品ページ、料金ページ、事例 |
| Go（特定サイトへ） | ブランドページ、About、店舗情報 |

上位表示されているページ群が示す意図と自分のページの型がズレていると、品質が高くても評価されません。

### 3-7. 鮮度とメンテナンス

- 新規公開コンテンツは**3〜5日でAI引用を獲得し始める**一方、AI検索における鮮度の減衰は速いという観測があります
- AIエンジンは新鮮で保守されているソースに高い信頼性を割り当てる傾向があります
- 従来SEOでもリライトは定番施策でしたが、AI時代は**更新の頻度と速さそのものが競争優位**になりつつあります

## 4. 評価されるサイトの条件 ― 構造と技術

### 4-1. 取得可能性（Retrievability）が最優先

ある評価フレームワークでは、各要素を証拠の強さで0〜10点にスコアリングした結果、**URLのアクセス可能性が9.5点で最上位、llms.txtが2.0点で最下位**という結果になりました。

**必須条件:**
- Googlebotがアクセスできる
- インデックスされている
- **検索スニペットを表示する資格がある**（`nosnippet`等で自ら塞いでいないか）
- JavaScript実行後にコンテンツが見える

> ページがクロール・インデックス・理解されなければ、あるいはスニペット表示の資格がなければ、有用な引用元にはなり得ません。

**重要な非対称：Googlebot と AIクローラーで基準が違います。**
上の「JavaScript実行後にコンテンツが見える」はGooglebotの基準です。GPTBot / ClaudeBot / PerplexityBot を含むほとんどのAIクローラーは**JavaScriptを実行せず、初期HTMLしか見ません**（詳細は §4-7）。したがってAEO観点での取得可能性の条件は「**JavaScript実行前のHTMLにコンテンツがある**」に置き換わります。ここは加点ではなく可視／不可視の二択です。

### 4-2. Googleが実際に見ている3つの層

Googleの自動システムはページを以下の3層で検査しています。

1. **ビジュアルレンダリング（スクリーンショット）** ― 人間から見た見た目。レイアウト、視覚的階層、読めるテキストの配置
2. **DOM構造** ― JavaScript実行後の完全なHTML。クリーンなタグ利用、適切な見出しフロー（h2、h3）、親子関係
3. **アクセシビリティツリー** ― ARIAロール、ラベル、セマンティックなランドマーク

**ラベルのない `<div>` だらけのコードは、AIエージェントの解析を妨げ、可視性を損ないます。** セマンティックHTMLは以前は「アクセシビリティのため」でしたが、今は直接的な可視性要因です。

### 4-3. 技術要件チェック表

| 領域 | 項目 |
|---|---|
| クロール／インデックス | robots.txt、XMLサイトマップ、canonical、noindex誤設定の排除、404/301の整理 |
| レンダリング | JS依存でコンテンツが消えていないか、CSR/SSRの選択 |
| ページ体験 | Core Web Vitals（LCP・INP・CLS）、モバイル対応、HTTPS |
| マークアップ | セマンティックHTML、見出し階層、alt属性、構造化データ |
| 情報設計 | パンくず、ナビゲーション、URL構造、内部リンク |

### 4-4. 構造化データの正しい位置づけ

- **AI Mode専用の構造化データは存在しません**
- 妥当なスキーマはGoogleのコンテンツ理解とリッチリザルト適格性を助けますが、**可視情報と一致している必要があり、掲載を保証はしません**
- 一方、対照実験では構造化データありでAI情報取得が約30%改善したという報告もあり（Aiso社の対照テスト）、「不要」ではなく「魔法ではない」というのが正確な理解です

### 4-5. サイト全体の質

- **テーマの集中:** 関連トピックを体系的にカバーし内部リンクで結ぶ（トピッククラスター）。特定テーマに絞った発信が専門性の獲得につながります
- **薄いページの整理:** サイト全体の質は平均で見られるため、重複・低品質・目的のないページの整理統合は有効です
- **ただし焦った対応は禁物:** 原因分析をせずタイトルや見出しを変更する、質の高いコンテンツまで削除する、順位回復目的で記事を大量追加する、といった対応は状況を悪化させます

### 4-6. ローカル／EC固有

- 実店舗や商品を持つ企業は、**GoogleビジネスプロフィールとMerchant Centerのフィードを正確に保つこと**。AI Overviewsは双方から情報を引いています
- SERP上の会話レイヤーである新しい Business Agent 製品も同じソースを参照します
- Googleのガイダンスは、強いローカル評判シグナルの重要性を明示しています

### 4-7. UI / UX / デザインはどれだけ効くか

「同じ文章を、凝ったデザインのサイトとWikipediaのような素っ気ないサイトに載せたら差が出るか」への回答。**差は出ますが、SEOとAEOで効き方がまったく違います。**

#### 前提：「デザイン」を2つに分ける

議論が混乱する最大の原因は、この2つが同じ言葉で呼ばれていることです。

| | 内容 | 検索エンジン／AIへの効き方 |
|---|---|---|
| **A. 装飾としてのデザイン** | 配色、フォント、余白、イラスト、アニメーション、世界観 | **直接的にはほぼ評価されない** |
| **B. 機能としてのUX** | 表示速度、モバイル対応、見出し階層、可読性、ナビゲーション、広告の非侵襲性、セマンティック構造 | **明確に効く** |

Wikipediaは **Aが最低クラス、Bが最高クラス**のサイトです。「素っ気ない＝UXが悪い」ではありません。

#### 影響度の目安（コンテンツの内容を10としたとき）

| 対象 | 影響度 |
|---|---|
| SEO（競合が拮抗していない） | **0.5〜1** |
| SEO（競合が拮抗している） | **2〜3** |
| AEO / LLMO（視覚デザインの美しさ） | **ほぼ0〜0.5** |
| AEO / LLMO（情報構造・技術実装） | **加点ではなく ×0 か ×1 のゲート** |
| CVR・売上などビジネス成果 | **5以上** |

数値は意思決定用の目安であり、Googleは重み付けを公開していません。

#### SEOへの効き方(1) ― 直接のランキング要因としては「タイブレーカー」

John Mueller氏はCore Web Vitalsについて「ランキングにおける巨大な要因ではない」「タイブレーカー以上ではあるが、コンテンツの関連性を置き換えるものではない。SEOとして取り組む価値はあるが、他をすべて捨ててこれに集中はしない」と述べています。**内容・被リンク・関連性が完全に同一なら、CWVが良いほうが上位に来る**という位置づけです。

ベンダー調査（算出根拠は非公開）では、CWVがランキングシグナルの約10〜15%を占め、3閾値すべて通過したサイトは競争的クエリで8〜15%の可視性向上、2026年3月コアアップデート後にLCP/INPが悪いサイトは競争的クエリで0.8〜4順位下落、といった数字が出ています。**「0.8〜4位」という幅がそのまま、競合状況によって影響が1にも3にもなることを示しています。**

#### SEOへの効き方(2) ― 本体は間接経路（ユーザー行動シグナル / NavBoost）

**デザインの良し悪しは、直接ではなくユーザーの行動を通じて効きます。**

2024年5月に流出したGoogle社内ドキュメントは3つのクリックシグナルを示しました。

| シグナル | 内容 |
|---|---|
| goodClicks | 検索結果にすぐ戻らないエンゲージしたクリック |
| badClicks | すぐ跳ね返るクリック（ポゴスティッキング） |
| **lastLongestClick** | **検索セッション中で最も長く注意を引いた結果。最も影響力が大きい** |

クエリ単位・ドキュメント単位・地域単位で約13ヶ月のローリングウィンドウで保持されるとされます。Google VPのPandu Nayak氏はDOJ反トラスト裁判の証言でNavBoostを「Googleの最も強いランキングシグナルのひとつ」と認めており、2026年時点ではAI Overviews / AI Modeを支えるシステムにも供給されているとされています。

```
読みやすい → 完読率が高い → 滞在が長い → lastLongestClick獲得 → 順位上昇
読みにくい → 途中離脱 → 検索結果に戻る → badClick → 順位下降
```

**ただしNavBoostが報いるのは「検索セッションを終わらせた結果であること」です。** 滞在時間そのものではなく「ここで探し物が終わった」という状態が評価されます。装飾の美しさではなく、**答えにたどり着きやすいか**が効くということです（§3-1「検索を終わらせられるか」と同じ話）。

なお §4-2 のとおりGoogleはビジュアルレンダリング（スクリーンショット）も検査層に含んでいるため、視覚的レイアウトはGoogleの評価対象には入ります。**ここがAI検索エンジンとの最大の違いです。**

#### AEO / LLMO への効き方 ― 視覚デザインはほぼ効かない

**AIクローラーはデザインを見ていません。**

- GPTBot / ClaudeBot / PerplexityBot を含むほとんどのAIクローラーは**JavaScriptを実行せず初期HTMLしか見ない**。OpenAIはChatGPTのブラウジングが完全なDOMレンダリングではなく簡略化されたテキスト抽出であるとし、PerplexityもHTMLスナップショット取得でJS非実行、AnthropicのClaudeもテキストベースのパースと説明されています
- 6つのAIアシスタント×60以上のWeb要素のテストでは、**CSSコメント、CSS変数、JSコメント、JS変数はLLMが見る前にコンバーターが除去**されており、「どのAIもページをスクロールしない」という結果でした

つまりフォント・余白・配色・アニメーション・装飾は、**AI側の入力に到達する前に捨てられています。影響度は実質ゼロです。**

これは §5-4 の Peec AI 調査（約3,000万ソース）で最も引用されるドメインが Reddit → YouTube → LinkedIn → Wikipedia だった事実と整合します。いずれも装飾がほぼゼロか、テキストが実体のサイトです。WikipediaはクリーンなセマンティックHTMLを使い、一方で多くのニュースサイトはクラス名が数週間ごとに変わる深くネストしたコンテナでコンテンツを包んでおり抽出を困難にしています。**凝ったデザインほどDOMが複雑化して抽出精度が落ちるという逆相関すら存在します。**

#### AEOで効くのは「構造」― ただし加点ではなくゲート

AEOにおける技術・構造の影響は「+3点」のような加点ではなく、**×0 か ×1 のスイッチ**です。

- クライアントサイドレンダリングのSPAでは、初期HTMLにコンテンツがあるかないかの二択で、**部分的な可視性は存在しない**。AIクローラーはレンダリングを待たず、2度目の試行もしない。生HTMLが空のシェルなら**サイト全体がAIから不可視**になる
- FCP（First Contentful Paint）が0.4秒未満のページは平均6.7件のChatGPT引用を得たのに対し、遅いページは2.1件だったというデータもある
- スキーマは「可視コンテンツを補強するものであって置き換えるものではない」。AIクローラーはまずページの可視テキストから意味を抽出するため、**優れたスキーマがあっても可視コンテンツが薄いページは最適化されていない**（§4-4と同じ結論）

#### 「きれいなデザイン」がマイナスに転じる典型パターン

| パターン | 何が起きるか |
|---|---|
| React/Vueのクライアントサイドレンダリング | AIクローラーから完全に不可視（×0） |
| 重いWebフォント・アニメーション・大量画像 | LCP/INP悪化 → SEOのタイブレーカーで負け、AI引用も減る |
| 図やインフォグラフィックに情報を載せる | **画像内テキストはAIに読まれない**（alt頼み） |
| カルーセル・アコーディオン・タブで情報を隠す | 初期HTMLに無ければAIに届かない／人間も見つけられない |
| 装飾優先で文章量を削る | そもそも内容で負ける |
| `<div>` だらけの非セマンティックHTML | Googleの構造解析とAIの抽出の両方を阻害（§4-2） |

**デザインを頑張っても上限があるのに対し、技術実装をミスると下限が0になる**という非対称性が、この問題の本質です。

#### 実務上の結論

1. **AEOだけを目的にデザイン投資をするのは筋が悪い。** AIはデザインを見ていない
2. **SEOでは「内容に差がないとき」に効く。** 内容で勝てるなら1程度、横並びなら3近く。**デザインで内容の弱さは補えない**
3. **投資対効果が最も高いのはB（機能としてのUX）。** 表示速度、モバイル、見出し階層、セマンティックHTML、SSR ― 検索・AI・人間の3者すべてに効く
4. **A（装飾）の本当の価値は検索の外にある。** ブランド想起、指名検索、CVR、リピート。ただし §5-1 のとおりブランドウェブ言及は AI可視性との相関 0.664 なので、長期的には迂回してAEOにも効く。**「このページのデザインが良いから引用される」ではなく「ブランドが認知されているから推薦される」という別経路**（§補足の Seer Interactive 仮説と同じ構図）
5. **理想形は「Wikipedia級の構造の上に、装飾を載せる」。** 装飾を先に決めて構造を後付けすると両方失う

## 5. サイト外の要因 ― ここが最大の変化点

**従来SEOとの最大の違いがここです。** 自社サイトのリライトより、外部での言及獲得のほうが効くケースが多くあります。

### 5-1. 相関データ

Ahrefsが**75,000ブランド**を対象に、AI可視性と相関する信号を調べた結果：

| 信号 | AI可視性との相関 |
|---|---|
| **YouTubeでの言及** | **0.737** |
| **ブランドのウェブ言及** | **0.664** |
| ブランド指名のアンカーテキスト | 0.527 |
| ブランド検索ボリューム | 0.334〜0.392 |
| **被リンク** | **0.218** |

上位3つはいずれも**サイト外のブランド信号**です。被リンク（従来SEOの中核指標）は、ブランド言及の約3分の1の強度にとどまります。

### 5-2. YouTubeの存在感

- YouTube言及は2026年データにおける最大の新発見で、単一指標として最強の相関を示しました
- **YouTubeはLLM回答の16%に登場**。GeminiはWikipedia、Redditと並ぶ主要参照プラットフォームとして扱っています
- Ahrefsの2026年7月データでは、**AI Overviewsで最も引用されるソースがYouTube（言及シェア21.1%）**
- メカニズムの推定：YouTubeの文字起こしがAI学習データの相当部分を占めており、複数チャンネルにまたがる独立した言及が「相互裏付け」として機能する

### 5-3. 流通の文脈（distribution context）が効く

同一記事8本を、5つの主要LLM × 944通りのプロンプト／プラットフォーム条件で検証した実験（Stacker、2025年12月）：

| 掲載場所 | 引用率 |
|---|---|
| ブランド自社サイト | **8%** |
| 第三者ニュースメディア経由 | **34%**（325%の上昇） |

2026年3月のより広いサンプルによる追跡調査でも、中央値で239%の上昇が確認されました。**変数はコンテンツの質ではなく、掲載されたドメインの権威性でした。**

### 5-4. 関連データ

- AirOps調査：**ブランド言及の85%が自社ドメインではなく第三者ページ由来**
- Muck Rack（2026年5月）：**AI引用の84%がアーンドメディア由来**
- AirOps（2025年10月）：ブランドは自社ドメインより**第三者ソース経由で6.5倍引用されやすい**
- Omniscient Digital（23,387ソース、2026年）：**ブランド名を含むクエリでは引用の57%**がレビュー、リスト記事、フォーラム、SNS、事例といった第三者ソースに向かう。従来型のソートリーダーシップやハウツーは約5%
- Peec AI（約3,000万ソース）：**最も引用されるドメインはReddit**、次いでYouTube、LinkedIn、Wikipedia

### 5-5. Redditの扱い（2026年調査）

- ChatGPT、Perplexity、Gemini、Google AI Overviewsを通じて**最も引用されるソーシャルソース**。特にPerplexityが顕著（46.7%、ChatGPTの約3倍）
- **投稿本体よりコメントのほうが引用される**（Perplexityでは78%がコメント）
- 引用されやすいフォーマット：**300〜600語、50以上のupvote、実名の経験、具体的なデータを含む長文の回答コメント**
- 50 upvote未満は引用率が有意に落ちる
- B2B SaaSでは上位5サブレディット（r/SaaS、r/marketing、r/entrepreneur、r/smallbusiness、r/startups）が約35%を占める
- **ただし:** 2026年時点で持続可能なのは本物のコミュニティ参加のみです。Reddit自身の検知システムとFTCの執行により、ステルスマーケティング的手法のリスクは高まっています。Googleも「不自然な言及の獲得」を明確に否定しています

### 5-6. 組織横断の示唆

```
広報・PR部門       → メディア掲載、プレスリリース配信 = AI引用の最大要因
カスタマーサクセス → レビュー獲得、事例化
マーケティング     → YouTube・SNSでの継続露出
SEO担当           → サイト側の取得可能性とコンテンツ品質
```

**SEO施策の所管を横断的に組み直す必要があります。**

- 現時点では価値を提供していれば依然として機能しますが、AI選択率は低下傾向にあるという業界調査もあります

### 6-5. ソートリーダーシップの位置づけ

思想的リーダーシップ記事は**直接の引用獲得手段ではなく、「権威インフラ」**として扱うべきです。それ自体が引用されるのではなく、リスト記事に載る権利や、記事が引用される土台となる**エンティティ理解とブランド権威**を積み上げます。

## 7. やらなくてよいこと ― Googleの公式Mythbusting

Googleのガイダンスは、明示的に以下を「Google検索においては無視してよい」としています。

> 「AEO/GEOハック」よりも有効なSEO戦略を優先すること。コンテンツの「チャンキング」、不要なAI向けテキストファイル（llms.txt等）の作成、不自然な言及（inauthentic mentions）の追求といった戦術は無視してよい。

### 7-1. llms.txt

**Google検索においては不要です。**

- 2026年6月のSearch Central ドキュメント更新で「Clarifying guidance on llms.txt files」として明記。**Google検索（生成AI機能を含む）に表示されるためにこれらのファイルは不要であり、可視性にプラスもマイナスも生じない**と明言
- Ahrefsが137,000サイトを分析（2026年5月）した結果、**既存のllms.txtファイルの97%はトラフィックがゼロ**（ボットも人間も一切取得していない）。残り3%のうちAI取得ボットの割合はわずか1.1%で、Slackbotのリンクプレビューのほうが PerplexityBot より多くファイルを取得していました。**存在しないllms.txtを探しに来たAIボットもゼロ**でした
- 理由の説明：Google検索は公開ウェブ全体を大規模にインデックスしているため、キュレーションされたインデックスファイルを必要としません

**例外 ― 作る価値があるケース:**
- 開発者ドキュメント、APIリファレンス
- Anthropic Claude や OpenAI のエージェントが有意なリファラーになっているサイト
- 根拠：**AnthropicはWriting for Agentsガイダンスでllms.txtを明示的に推奨**、OpenAIもAgents SDKとAgentic Commerce Protocolで使用、Chromeの Lighthouse 13.3 は2026年5月初旬に Agentic Browsing 監査カテゴリを追加し、このファイルの有無をチェックするようになりました
- 論理：推論時にサイトを操作するAIエージェントには、インデックスも時間も忍耐もない。だからキュレーションされた要約が効く

**作らないほうがよいケース:**
- Google検索の可視性だけが目的
- 1万ページ以上の規模で、ファイルを正確に保つ保守コストが現実的な負担になる
- 他の優先施策にリソースが逼迫している

### 7-2. チャンキング（機械的な細切れ化）

「Q&A形式のH2見出しの下に40〜60語の回答ブロックを置く」という定型的なリライト提案について、Googleの立場は明確です。**AIが理解するためにコンテンツを細切れにする必要はありません。** Q&A構造は強調スニペットと人間の読者にとって依然有効ですが、機械的なチャンキングがAIから追加の評価を得ることはありません。

### 7-3. AI向けの文体書き換え

「個性を削ぎ、代名詞を固有名詞に置き換え、散文を箇条書きに平坦化する」といった提案について、Googleは**現代のAIは同義語と意味を十分に扱える**としています。

### 7-4. AI専用スキーマ

存在しません。妥当なスキーマは有用ですが、「AI向けの特別なマークアップ」というものはありません。

## 8. やってはいけないこと ― スパムポリシー

Googleのウェブ検索スパムポリシーが対象とする違反：キーワード詰め込み、リンクスパム、機械生成トラフィック、マルウェア、誤解を招く機能、**スケールされたコンテンツの濫用**、スクレイピング、**サイトの評判の濫用**、不正なリダイレクト、質の低いアフィリエイト、UGCスパム、バックボタンハイジャック。

### 8-1. スケールされたコンテンツの濫用（最重要）

- **定義:** ランキング操作を主目的として大量のページを生成すること。**AI生成・人間執筆・スクレイピングのいずれかを問わない**手法非依存のポリシー
- 判断基準は**意図（ランキング操作）と結果（ユーザー価値の乏しさ）**
- **AI生成コンテンツ自体は違反ではありません。** Googleは生成方法ではなく有用性を評価します。編集され、正確で、実際に役立つAI支援コンテンツはポリシー内。編集を経ない大量生産が降格を招きます
- 2024年3月にポリシー新設、2025年8月のスパムアップデートでSpamBrainの検知を強化、2026年6月のスパムアップデートもコンテンツレベルの違反を主対象としています

### 8-2. サイトの評判の濫用（パラサイトSEO）

- **定義:** 権威あるドメイン上に、第一者による編集監督がほとんどない第三者ページを公開し、ホストサイトの権威シグナルを利用してランキングを操作すること
- 2024年3月に手動対応のみのポリシーとして開始 → **2025年8月のスパムアップデートで完全にアルゴリズム的な執行へ移行**
- **これは「回復すべきペナルティ」ではなく、権威評価の構造変化です。** Googleがドメインのセクションを親ドメインの権威から切り離して独立に評価できるようになったため、パラサイトSEOの中核メカニズム自体が機能しなくなりました
- **同じ枠でリスクが上がった隣接戦術:**
  - 権威指標（DA/DR等）を基準に選定した大量ゲスト投稿キャンペーン
  - 「Write for us」を大々的に受け入れているサイトへの寄稿
  - ニッチエディット／リンク挿入サービス
- 2025年11月にはこのポリシーをめぐりEUの調査が開始されています

### 8-3. AI回答の操作（2026年5月新設）

**2026年5月15日、Googleはスパムポリシーの定義をAI OverviewsとAI Modeを含むよう書き換えました。AI回答を操作することはスパムです。**

これは「AIに引用させるための不自然な言及の買い付け」を明確に射程に入れています。Google自身がガイダンスで「inauthentic mentions（不自然な言及）の追求」を否定している点と整合します。

### 8-4. 2026年のアップデート履歴（参考）

| 時期 | 内容 |
|---|---|
| 2026年3月13日〜27日頃 | コアアップデート。E-E-A-Tの評価精度向上が最大の変更点。55%以上のサイトで変動、3月20日以降に第二波 |
| 2026年3月 | スパムアップデート。既存ルールの執行精度向上。SpamBrainの調整。リンクスパムとサイト評判濫用は対象外 |
| 2026年5月 | コアアップデート。品質・関連性シグナルの再調整 |
| 2026年5月15日 | スパムポリシー定義をAI Overviews/AI Modeに拡張 |
| 2026年6月24日頃 | スパムアップデート。リンクスパムとサイト評判濫用を明示的に除外＝**コンテンツレベルの違反が対象**（スケールされたコンテンツの濫用、クローキング、キーワード詰め込み） |

**コアアップデートとスパムアップデートは別システム・別の対処法です。** コアアップデートではルールを破っていなくても順位が下がり得ます（アルゴリズムが重視する品質シグナルが変わった、競合が改善した、など）。スパムアップデートは文書化された特定のルール違反に対する罰則です。トラフィック低下の切り分けはまず日付から行います。

## 9. 効果測定

### 9-1. 順位だけを見ない

前述のとおり、AI引用と検索順位の重複は限定的です。**ブランド名やユースケースを含むプロンプトを定点観測し、自社が挙がるか／どのURLが引用されているかを直接トラッキングする**必要があります。

### 9-2. 追うべき4つの信号

1. **Presence（出現）:** そもそもAI回答に自社が登場するか。プロンプト単位で測る。登場しなければ可視性はゼロ
2. **Citations（引用）:** どのURLが引用元として挙がっているか
3. **Sentiment（論調）:** どう描写されているか。正確か
4. **Share of Voice（競合比）:** 競合と比べた露出比率。競合が引用されている外部ページは、AIが生成するベンダー候補リストを形作っているため、そこを追う価値がある

### 9-3. ビジネス指標への接続

- Google Search Console のAI検索レポート（AI検索の可視性とオプトアウト制御が追加されています）
- AI経由の参照トラフィックとコンバージョンの計測
- 参考データ：**LLM経由のリードは他チャネル比で2〜6倍高いコンバージョン率**という企業報告があります（母数が小さい段階の数字である点に注意）

## 10. 実装チェックリスト（優先順位付き）

### 優先度1 ― 取得可能性（これが欠けると他が全部無効）

- [ ] 主要ページがインデックスされているか（Search Consoleで確認）
- [ ] `nosnippet`、`max-snippet` 等でスニペット表示を自ら塞いでいないか
- [ ] robots.txt で必要なクローラーをブロックしていないか（AIクローラーの許可方針を明示的に決める）
- [ ] JavaScript実行後にコンテンツが見えるか（Googlebot基準のレンダリング確認）
- [ ] **JavaScript実行“前”のHTMLにコンテンツがあるか**（AIクローラー基準。§4-7。ここは×0か×1）
- [ ] 重要な情報を画像・カルーセル・アコーディオンの中だけに置いていないか（§4-7）
- [ ] canonical、noindex の誤設定がないか
- [ ] Core Web Vitals（LCP・INP・CLS）とモバイル対応
- [ ] HTTPS

### 優先度2 ― コンテンツの中身

- [ ] 各ページの検索意図と、ページ型が一致しているか
- [ ] 「そこにしかない情報」が入っているか（独自データ、事例、実測、現場知見）
- [ ] 具体的な数値と出典が入っているか（一般論で埋めていないか）
- [ ] 結論が冒頭にあるか
- [ ] 執筆者・監修者・所属・更新日が明示されているか
- [ ] 自社カテゴリで実際に引用されているページ型を調べたか（業種ごとの「引用の指紋」）

### 優先度3 ― サイト全体

- [ ] テーマが絞れているか、関連記事が内部リンクで結ばれているか
- [ ] 薄いページ・重複ページの棚卸し（ただし焦った大量削除はしない）
- [ ] セマンティックHTML（見出し階層、ランドマーク、ARIA）
- [ ] 構造化データが可視情報と一致しているか
- [ ] ローカル／ECならGoogleビジネスプロフィールとMerchant Centerの精度

### 優先度4 ― サイト外（比重が上がった領域）

- [ ] 業界メディア・ニュースメディアへの掲載機会をつくる仕組みがあるか
- [ ] レビューサイト・比較メディアでの掲載と評価
- [ ] YouTubeでの継続的な露出（自社チャンネル＋第三者による言及）
- [ ] コミュニティ（Reddit、業界フォーラム、Qiita/note等）での**本物の**参加
- [ ] Wikipedia等の参照可能なエンティティ情報の整合性
- [ ] 指名検索を増やすオフライン／広告施策

### 優先度5 ― 更新運用

- [ ] 主要記事の更新サイクルが定義されているか
- [ ] 情報の陳腐化を検知する仕組みがあるか

### 優先度6 ― やらない／避ける

- [ ] llms.txt は「開発者ドキュメント／エージェント向けサイト」以外では後回し
- [ ] 機械的なチャンキング、AI向け文体書き換え、AI専用スキーマは不要
- [ ] AI大量生成の未編集コンテンツを量産していないか
- [ ] 権威指標ベースの大量ゲスト投稿、リンク購入、ニッチエディットを使っていないか
- [ ] AI回答を操作する目的の不自然な言及買い付けをしていないか

## 補足 ― 引用は「参考文献」であって「ブレインストーミング」ではない？

Seer Interactive の2026年研究は、362,388件の回答にわたる6つの独立した行動テストをもとに、次の仮説を提示しています。

> LLMはまず学習データからどのブランドを推薦するかを決め、**その後で**その選択を裏付けるソースを探している。引用は参考文献リストであって、ブレインストーミングではない。

これが正しければ、戦略上の含意は重大です。**引用最適化だけでは、弱いブランド権威を覆せません。** AIはどのブランドを推薦するかを、どのページを引用するかを選ぶ前に決めてしまっているからです。

また ChatGPT では、2026年7月時点で「official site」「official docs」「official pricing」「official product」といった公式性を示す語でクエリをファンアウトする挙動が観測されており、**すでに認識しているブランド名を軸にサブ検索を展開する**傾向が強まっているという報告もあります。

いずれも仮説段階ですが、「小手先の最適化より、ブランドそのものの認知と実体を積む」という方向性を支持するものです。
