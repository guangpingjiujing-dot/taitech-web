# taitech-menta-compliance

MENTA 上で taitech.dev などの外部 URL を扱ってよいかの判定。

## 結論: 下記はすべて可（MENTA 運営に照会済み / 2026-08-26 回答）

| やりたいこと | 判定 |
|---|---|
| 契約中のメンティーに 1:1 で教材 URL を渡す | 可 |
| 同じ場面でアフィリエイトを含む書籍ページの URL を渡す | 可 |
| ナレッジ記事に学習内容を書き、補足で自サイトにリンク | 可 |
| ナレッジ記事の主題が書籍紹介で、アフィリエイトを含むページへ誘導 | 可（アフィリエイト表記を推奨） |
| 無料ツールの公開・更新の告知記事 | 可（頻度に注意。下記） |
| プロフィールの自己紹介文に自サイト URL | 規約上は可。**ただし実装上できない**（下記） |
| プラン説明文に教材 URL | 可 |
| Qiita / Zenn / X / note など自サイト以外へのリンク | 可（上記と同じ扱い） |

運営は外部発信を**歓迎する立場**を明示している。

> メンター様のブランディングやプロモーションとなり結果としてMENTAでの契約の可能性が高まることや、メンティー様からもメンター様の能力やお人柄を知る重要な情報源になると考えております。

**逐語の回答は `inquiries/2026-08-22-external-links.md`。** 上の表の各行は
そこの設問 1〜9 に 1:1 で対応する。判定を人に説明するときは、この表ではなく
回答本文を引くこと。

## 実装の挙動（2026-08-26 に自分の投稿で実測）

ナレッジ記事（`/post/detail/179723/Gtu0Lxrl8bg1sTca0n38`）での実測。

- **URL は自動リンク化される。** 本文に素の URL を書けば `<a>` になる。手で書式を作らなくてよい
- **クエリ文字列は保持される。** UTM 4 個がすべて無傷で残る
- **外部リンクは `rel="ugc nofollow"`。** つまり**被リンク施策としては効かない**。
  menta は note と同じ「露出面・送客」の枠で評価する（`docs/strategy/growth.md` §1 診断 3-bis）
- **noindex は付かない。** `menta.work/robots.txt` に `sitemap-posts.xml` と
  `sitemap-users.xml` があり、記事もプロフィールもインデックス対象
- **`<title>` は記事タイトル + ブランド接尾辞**（`… | 【MENTA】No1.メンターサービスで…`）
- 本文の `■` などの記号見出しは HTML 側で見出し要素に変換される。Markdown 記法は不要

## 制約

- **プロフィールの自己紹介文には、規約上は可でも URL を入れられない。**
  入力バリデーションで弾かれる（2026-08-26 に実機で確認）。
  **規約の可否と実装の可否は別**なので、可と分かっても実際に入るかは手で試すこと。
  代替は**プラン説明文**（こちらは URL を入れられる）
- **頻度で断られうる。** 告知記事について運営は「内容や頻度によっては公開をお断りする
  可能性がございます」と留保している。連投しない
- **アフィリエイト表記は MENTA 側では「推奨」だが、景表法のステマ規制は別に効く。**
  サイト側の開示表記は運営回答に関わらず必要（`AGENTS.md` の Amazon Associates ガードレール）
- **可否の判断基準は開示されなかった。** 「どこまでが宣伝か」の線引きを尋ねた設問 10 は
  回答を拒否されている。したがって利用規約 8条2項(15)(23) とガイドライン 15 の
  **裁量条項はそのまま残り、上の表に無い形は保証されていない**
- **書籍紹介主題の記事（設問 4）には個別回答が無い。** 続く設問 5 の回答が 4 を
  まとめて答えたものと読んでいるが、それは解釈。争点になる場面では再照会する

## 条文の現状

引用は `references/*.txt` から逐語。**行番号は改訂でずれるので条番号で参照する。**

### 利用規約 第8条第2項（禁止行為）

- **(4)** 本サービスと競合するサービス等を宣伝する行為及びこれに類する行為
- **(14)** 本サイトを介さずに行う直接取引やそれを勧誘する行為、又は、勧誘に応じる行為。（本サービスで取引開始をしたユーザーと再度取引する場合を含む）
- **(15)** 利用ユーザーの目的と合致しない宣伝広告及び誤解又は損害等を与えるおそれのある行為
- **(23)** その他当社が不適切であると判断する行為

同条は「該当し、又は**該当するおそれがあると当社が判断した場合**には、事前に通知することなく」
利用停止・退会等の措置を取れると定めている。実務上は (15) と (23) がすべてを飲み込む。

### ガイドライン

- **1. 直接取引を行う行為**
  > MENTAを介さずに行う直接取引、勧誘・宣伝行為を禁止しております。
- **11.**（宗教勧誘・ネットワークビジネス）
  > 宗教への勧誘、マルチ商法、ネットワークビジネスの勧誘・営業行為を行うことはできません。**それに付随し**MENTAから外部サイトでの予約申込口に誘導する「広告的」な使い方を禁止します。
- **15. 当社が不適切と判断したプラン/募集** — 裁量条項

### 読み違えやすい 3 点

1. **外部サイトへの誘導を一般に禁じる条文は無い。** 8条2項(10) は
   「猥褻な情報又は青少年に有害な情報の送信、それらを掲載する他のウェブサイトへの誘導」で
   **猥褻情報限定**。一般の外部リンクの根拠にはならない
2. **ガイドライン 11 の外部誘導禁止は「それに付随し」で宗教勧誘・マルチ商法の文脈に係る。**
   単独で「外部サイトへの誘導は一律禁止」と読んではいけない
3. **ガイドライン 14 の列挙にアフィリエイトへの言及は無い**（`grep -c アフィリエイト` が 0）。
   近いのは「ネットワークビジネス・情報商材販売に関する内容」「金融商品販売につながる内容」

**マナー（`menta-manner.txt`）に外部リンク・誘導の記述は無い**（同 grep が 0 件）。
外部誘導の可否を調べるときに読む必要はない。

## エビデンスの置き場

| ディレクトリ | 中身 | 性質 |
|---|---|---|
| `references/` | 利用規約 / ガイドライン / マナーの本文 | MENTA の**公開ページ**。`refetch.sh` で再取得できる |
| `inquiries/` | 運営への照会の送信本文と回答 | **再取得できない**。だから `references/` には置かない |

`references/` の運用ルールは `references/README.md`。
`inquiries/` は `<YYYY-MM-DD>-<slug>.md`（背景と回答）と同名 `.txt`（送信本文）の 2 点セット。

### 更新検知

規約・ガイドラインは改訂される（表示更新日はガイドライン 2023-02-27 / マナー 2021-02-17）。
**MENTA まわりの判断をする前に再取得して差分を見る。**

```bash
bash .claude/skills/taitech-menta-compliance/references/refetch.sh
git diff -- .claude/skills/taitech-menta-compliance/references
```

- 差分ゼロなら、この SKILL.md の記述をそのまま信じてよい
- **差分が出たら、差分を読んでから「条文の現状」節を直す**。
  条文が動いたのに SKILL.md が古いままだと references を置いた意味が消える
- ページ外枠（ナビ・フッター）だけの変更でも sha256 は動く。中身を見て判断する
- HTTP 200 以外なら `refetch.sh` は異常終了する。URL の移動を疑い `SOURCES` を直す
